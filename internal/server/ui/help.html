How to use PrintDex

Scan a guest's ticket, they are checked in on EventzFlow, and their badge prints. This page covers setup, daily use, and what to do when something goes wrong.

Set up a station (first time)

  1. Connect and switch on the printer Install its driver if the computer doesn't list it already. It must appear in Printers & scanners (Windows) or Printers & Scanners (macOS) before PrintDex can use it. Load the label stock.
  2. Open PrintDex and go to Settings → Event Press the gear icon at the top right, then the Event tab.
  3. Enter the three connection details
    • Website address — your EventzFlow address, starting with https://.
    • Event ID or slug — either the event's number or the short name in its web address. Both work.
    • API key — the key for this event, from your EventzFlow admin. Type it in full the first time; leaving the box empty later keeps the saved one.
    Press Save. A green line under Event ID or slug shows the event's name, ID and slug. If you see that, the connection is right.
  4. Check the printer: Settings → Station Under Printer you should see your printer's name. Press Test print: a bordered page with the time should come out.
  5. Set up the badge Press Edit badge layout on the main screen. Set the paper size to your label stock, choose what to print, and check the live preview. Save. See Badge layout.
  6. Choose who gets no badge (optional) Settings → Event → Check in without a badge: tick the ticket types that should be checked in but not printed (for example staff).
  7. Try one real scan Scan a test ticket. You should see "Checked in — badge printing" and a badge come out. Then run the self-check once so you know everything is green before doors open.

Using it during the event

Scanning

Keep the cursor in the Ticket code box (it takes focus back by itself). Point the scanner at the guest's QR code. The scanner types the code and presses Enter, and PrintDex does the rest: looks the ticket up, checks the guest in, prints the badge. You do not need to press Check in & print when using a scanner; that button is for typing a code by hand.

If several guests are scanned quickly, they wait in line and are handled one at a time, in order.

Guest has no QR code

Use Search by name, email or phone under the scan box. Type at least 2 letters of a name, a full email address (it needs an @), or at least 4 digits of a phone number. Results show paid tickets only, up to 10; type more to narrow them down. Press Check in on the right guest, or Reprint if they are already in.

Keyboard: ↓ moves from the box into the results, ↑/↓ move between guests, Enter acts on the selected one, Esc clears the search and returns to the scanner.

Print a badge without checking anyone in

Open Manual entry, fill in the fields, and press Print badge. Nothing is sent to EventzFlow. Useful for walk-ups, spare badges and testing the layout. Every row in Recent also has a Reprint button.

The Recent list

Recent lists this session's scans, newest first, with a count of how many checked in and how many were repeats. It is kept only while the window stays open: reloading or restarting empties it (the check-ins themselves are safe on EventzFlow). Clear empties it on screen.

Badge layout

The badge is a stack of lines centered on the label: the guest's name, ticket type, optional details, and a QR code of the ticket. You choose what goes in the stack and in which order; PrintDex picks the text sizes.

  • Paper size must match your label stock in millimetres (20–500 mm each way). A mismatch is the most common reason for badges printing off the label.
  • Fields: name, ticket type, company, title, country, table number, ticket group, ticket role, plus up to 6 custom fields you add. A field with nothing in it for a guest is skipped.
  • Sizes are automatic. Names use the biggest size that fits, on one line or two. A badge with few fields grows its text to fill the label (within limits, so the name stays the biggest thing). A crowded badge shrinks the QR code first (never below about 14 mm, so it stays scannable), then the text, down to 8 pt.
  • Adjust lets you change an element's size (0.5×–2×), make it bold, or nudge it up to 10 mm. Vertical offset slides the whole stack up or down by up to 80 mm.
  • Saved layouts keep different designs (for example one per ticket class) so you can switch with one click.
  • The preview is drawn the same way as the print, so what you see is what comes out. Unsaved edits show in the preview; printing uses the last saved layout.
  • Direct thermal tags (Settings → Event): turn on if text prints with missing dots on rough or thick tags. It prints bolder.

Self-check

Press Run checks to test each part of the station in turn. Anything that fails says what to do. Run it before doors open, and again whenever something looks wrong.

The report contains the version, printer, event name and which checks passed. It never contains the API key.

Something went wrong

Find what you see on screen, open it, and follow the steps. Messages in code style are the exact words PrintDex shows.

Connecting to EventzFlow
The scan box says "Connect your event first", or a banner says "Connect EventzFlow to scan tickets."

One of the three connection details is missing.

  1. Settings → Event.
  2. Fill in Website address, Event ID or slug and API key, then Save.
  3. Confirm the green line shows your event's name.
Event not found. Check the event ID or slug.

EventzFlow does not know an event by what was entered.

  1. Copy the ID or slug again from the event in EventzFlow; check for typos or a trailing space.
  2. Try the other form: if the slug fails, use the numeric ID, or the other way round.
  3. Check the Website address: an event that lives on one EventzFlow server (for example staging) isn't found on another (production).
Not authorized. Check your API key. or …Check your API key permissions.

The API key is wrong, expired, belongs to another event, or isn't allowed to check guests in.

  1. Ask your EventzFlow admin for the event's key and confirm it can check guests in.
  2. Settings → Event → paste the full key → Save. (An empty key box keeps the old one, so the new key must be typed in.)
  3. Run the self-check: "API key accepted" should turn green.
Network error contacting backend: …

PrintDex couldn't reach EventzFlow at all. The text after the colon says why: connection refused (nothing listening at that address), no such host (address misspelled or no internet/DNS), timeout (network too slow or blocked), certificate (the computer's clock is wrong, or a venue network is intercepting secure connections).

  1. Check the computer's internet connection; open the Website address in a browser on the same computer.
  2. Check the address begins with https:// and has no extra path at the end.
  3. Check the computer's date and time are right.
  4. On a venue network, ask whether outgoing HTTPS is restricted or a proxy is needed.
  5. No guest is checked in while this error shows, so it is safe to scan again once the connection is back.
The backend address is not valid.

The Website address isn't a usable address.

Re-enter it in full, for example https://app.eventzflow.com, with no spaces.

Lookup failed (500) / (502) / (503) or similar

EventzFlow itself had a problem answering.

  1. Wait a moment and scan again; nobody was checked in by the failed attempt.
  2. If it keeps happening, tell your EventzFlow admin, with the time and the ticket code.
  3. Meanwhile, you can still print badges by hand with Manual entry.
Scanning and tickets
Ticket not found for this event.

EventzFlow has no ticket with that code in this event.

  1. The ticket may belong to a different event, or have been cancelled or deleted.
  2. The code may be damaged by the scanner (extra characters at the start or end, wrong letters). Look at what was typed into the box; see "The scanner types the wrong characters" below.
  3. Find the guest with Search by name, email or phone instead.
A red "Not checked in" with a message such as "Ticket is not paid"

EventzFlow refused the check-in and said why. PrintDex shows its message as it is. The guest is not checked in and no badge is printed.

  1. Read the message under the name.
  2. Fix the cause in EventzFlow (for example confirm the payment), then scan again.
"Already checked in" but the guest says it's their first time

The ticket really was scanned before. The line "First scanned … by … at …" says when and where, when EventzFlow knows.

  1. Check the time and the operator or gate. Another station, another PrintDex, or RfiDex may have scanned it.
  2. If it was a genuine earlier scan and they only need a badge, press Reprint.
  3. If you suspect a shared or copied ticket, handle it as your event rules say; PrintDex does not undo check-ins.
The scan box shows "Scanner paused", or the scanner types nothing

The scan box doesn't have the keyboard focus, or a window is open on top of it (Settings pauses the scanner).

  1. Close Settings, then click the scan box.
  2. Check the scanner is connected and has power (cable, or Bluetooth paired and charged). A scanner is a keyboard to the computer.
  3. Test the scanner in a text editor. If it doesn't type there either, the problem is the scanner or its connection, not PrintDex.
The scanner types the code but nothing happens

The scanner isn't sending Enter after the code, so PrintDex never gets the signal to start.

  1. Press Check in & print by hand to confirm the code works.
  2. Set the scanner to send "Enter" (carriage return) after each scan. The scanner's manual has a setup barcode for this.
The scanner types the wrong characters (letters swapped, symbols instead of digits)

The scanner's keyboard language doesn't match the computer's.

Set the scanner's keyboard layout to the one the computer uses (setup barcode in the scanner manual), or change the computer's input language to match.

I scanned a ticket twice and nothing happened the second time

A repeat of the same code within about 3 seconds is ignored on purpose, to stop a double-read from checking in or printing twice. After that, a second scan shows "Already checked in".

Printing
Printing failed: no printer found; connect a printer and try again

The computer lists no printer.

  1. Check the printer's power and cable, and that its driver is installed.
  2. Confirm it appears in Printers & scanners (Windows) or Printers & Scanners (macOS).
  3. Settings → Station → Refresh. The printer name should appear.
  4. Press Retry print on the badge that didn't print. The guest is already checked in; do not rescan.
It prints, but on the wrong printer

PrintDex uses, in order: the PRINTER_NAME setting, the only installed printer, the computer's default printer, then the first one found.

  1. Quick fix: set the label printer as the computer's default printer.
  2. Firm fix: put PRINTER_NAME=Exact Printer Name in a .env file next to PrintDex and restart it. See Reference.
Printing failed: lp: … (macOS)

macOS's print system (CUPS) refused the job; the words after lp: are its reason.

  1. Open System Settings → Printers & Scanners, open the printer's queue, and make sure it isn't paused or showing an error. Resume it.
  2. Remove stuck jobs from the queue.
  3. If it still fails, remove and add the printer again with its driver.
  4. In Terminal, lpstat -p -d shows printer state and the default; lpstat -o shows queued jobs.
Printing failed: could not open printer "…" (Windows)

Windows has no printer with exactly that name, usually because it was renamed, removed, or PRINTER_NAME is misspelled.

  1. Check the name in Printers & scanners and copy it exactly.
  2. Fix or remove PRINTER_NAME in the .env file, then restart PrintDex.
printer "…" refused the job, could not start a page, did not accept the job or rejected the badge image (Windows)

Windows reached the printer but it wouldn't take the job: usually offline, paused, an error light, a stuck spooler, or a driver that doesn't handle images well.

  1. Look at the printer: power, paper/label jam, lid closed, error light.
  2. Open the printer's queue in Printers & scanners; if it says offline or paused, fix that; cancel all stuck jobs.
  3. Restart the Print Spooler service (Services → Print Spooler → Restart).
  4. Reinstall the manufacturer's own driver (not a generic one).
  5. Press Test print in Settings → Station to confirm. Then Retry print on the badge.
"Checked in — badge didn't print"

The check-in worked; only the printing failed. The reason is under the guest's name.

  1. Fix the cause (see the printer entries above).
  2. Press Retry print.
  3. Do not scan the ticket again.
Test print works, but real badges don't

The printer is fine; the problem is in the badge or the data.

  1. Open Manual entry and press Print badge. This prints a badge with no EventzFlow involved. If it works, the layout and printer are fine and the problem is the ticket's data or the connection.
  2. If it fails, look at the message and the layout's paper size.
The badge looks wrong
The text sits off the label, is cut off, or the printer feeds a blank label

The paper size in the layout doesn't match the label stock or the printer's own page size.

  1. Measure the label (width × height in millimetres). Set the same in the layout, and in the printer driver's page/paper size.
  2. Use Vertical offset or an element's nudge to shift things a few millimetres.
  3. Calibrate the printer's label (gap) sensor as its manual describes, especially after changing stock.
The badge comes out upside down (Windows)

On Windows, PrintDex turns every badge 180° to suit how the station printers feed labels.

  1. Set rotation 180° in the printer driver's preferences to cancel it, or
  2. ask the maintainer to switch rotate180 off in the code.
Text is faint, or has missing dots and broken strokes
  1. Turn on Direct thermal tags (Settings → Event). It prints bolder.
  2. Raise the printer's darkness/density in the driver, or slow the print speed.
  3. Clean the print head; rough or very thick tag stock drops dots.
Text is too heavy or blobby
  1. Turn Direct thermal tags off if it is on.
  2. Lower the printer's darkness/density.
A name is too small, or breaks over two lines

That is the automatic sizing: long names use two lines and a smaller size so they fit; very long ones go down to 8 pt.

  1. Make the paper wider, or remove other fields so more room is left.
  2. Use Adjust on the name to scale it up or down (0.5×–2×).
The QR code won't scan
  1. Give it more room: remove a field or use a bigger label. On a crowded badge the QR code is shrunk to make space, and below about 14 mm it scans poorly.
  2. Check print darkness (a faint print scans badly); avoid Direct thermal mode if the QR looks blurred.
  3. Test with the scanner on a freshly printed badge in good light.
The preview looks right but the printed badge differs in size or position

The printer driver is rescaling the page.

  1. In the driver, set scaling to 100% / "actual size" (not "fit to page") and the page size to the label size.
  2. macOS: if prints come out tiny or huge, set PRINT_DPI to the printer's resolution (203 or 300) and restart. See Reference.
The station itself
The "Station online" light is red, or the page stops responding
  1. Settings → Station → Restart. If the page won't respond, close PrintDex and open it again.
  2. Nothing is lost: check-ins are already on EventzFlow.
the local API port is in use; is another copy running?, or RfiDex can't reach the printer

Another program is already using port 8000 on this computer, most often a second copy of PrintDex or the old event-printer app. RfiDex looks for PrintDex at http://127.0.0.1:8000.

  1. Quit the other copy (Task Manager on Windows, Activity Monitor on macOS), then open PrintDex again.
  2. The window can still print while the port is busy; only RfiDex's link is down.
  3. To use a different port, set PORT, but RfiDex must then be pointed at the same port.
The window is blank or shows an error (Windows)

Windows needs Microsoft's WebView2 runtime to show the window. The installer normally adds it.

Install "Microsoft Edge WebView2 Runtime" from Microsoft, or reinstall PrintDex with an internet connection.

My settings disappeared after an update or reinstall

Settings live in one file, not inside the app. Updating and reinstalling keep it. See the path under Reference.

  1. If the file is gone, re-enter the Event details and layout.
  2. A station coming from the older event-printer app imports that app's settings the first time PrintDex starts, only if PrintDex has no file of its own yet.
Updates
"Self-update is off in this build"

This copy was built without an update key (a development or unsigned build), so it can only check, not install.

Install the latest release from the releases page instead.

Couldn't check for updates: …

PrintDex couldn't reach the release page (no internet, or the release server is blocked or down).

Check the internet connection and try again. Updates are optional; the station keeps working.

the download's signature is not valid

The downloaded file wasn't signed by the publisher, or was damaged on the way. PrintDex refuses to install it.

Don't install it. Download the installer again from the official releases page, and tell the maintainer if it repeats.

Couldn't install the update: … or Updated, but couldn't restart.
  1. If it says it couldn't restart: close PrintDex and open it again; the update is already in place.
  2. If it couldn't install: the program's folder isn't writable (for example it was copied into a protected folder). Reinstall with the installer.

When it isn't obvious what's wrong, narrow it down by testing one part at a time:

Where to look

  • Activity log — Settings → Station. Every scan, print and error is written here with the time: scanning T-001…, printed + checked in: Name, scan failed: …. Start here.
  • Recent on the main screen shows each scan's outcome and, for failures, the reason.
  • Scan timing. Each scan reports how long its steps took (lookup, check-in, print, total, in milliseconds). It is written to PrintDex's own log when it is started from a terminal. If lookup or check_in is slow, the network or EventzFlow is slow; if print is slow, the printer, driver or spooler is.
  • Status pages. With PrintDex open, visit these in a browser on the same computer: http://127.0.0.1:8000/health (version and chosen printer), /printers (installed printers), /config (settings, key hidden), /event (which event is connected), /update/status.
  • Windows printing. Printers & scanners → your printer → Open print queue shows stuck or failed jobs. Services → Print Spooler can be restarted.
  • macOS printing. In Terminal: lpstat -p -d (printers and default), lpstat -o (queued jobs). The CUPS page http://localhost:631 shows each job's error.

When you ask for help

Send: the report from the self-check ("Copy report"), a screenshot of the screen and of the Activity log, roughly when it happened, and the ticket code involved. That is usually enough to find the cause without anyone having to be at the station.

Reference

Settings that live outside the window

Set these as environment variables, or put them in a plain text file named .env in the same folder as the PrintDex program, one NAME=value per line. Restart PrintDex after changing them.

NameDefaultWhat it does
PRINTER_NAMEautomaticThe exact name of the printer to use. Automatic: the only printer, else the computer's default.
PORT8000The port the local address uses. RfiDex expects 8000.
HOST127.0.0.1Who may reach this station. Leave as is. 0.0.0.0 opens it to the whole venue network, and it has no login.
PRINT_DPI203macOS/Linux: the printer's resolution (203 or 300). Windows reads it from the driver.
HEADLESSoffAny value: run without a window.

Where PrintDex keeps its settings

Windows: %APPDATA%\printdex\config.json · macOS: ~/Library/Application Support/printdex/config.json

The file holds the API key in plain text, readable only by the person who owns it. On a shared computer, use a separate user account for the event.

Good habits

  • Run the self-check and a test print before doors open.
  • Keep a stack of spare label rolls and a spare printer cable at the desk.
  • If the printer jams, fix it and press Retry print; never rescan the guest.
  • Only the printer that PrintDex is using should be the computer's default, to avoid badges going to an office printer.
